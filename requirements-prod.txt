# Runtime dependencies for the FastAPI service only — a trimmed subset of
# requirements.txt (which is the full dev/pipeline environment: notebooks,
# ballchasing data collection, tests). Docker's backend stage installs from
# this file instead, since none of the dev-only packages (jupyter, requests,
# pipreqs, pytest, ...) are imported by src/api or the model classes it loads.
#
# Installed with `pip install --no-deps` (see Dockerfile), so this list is
# the full transitive closure, pinned explicitly — not just the packages
# src/ imports directly. That's deliberate: xgboost's Linux wheel declares
# an unconditional dependency on nvidia-nccl-cu12 (~300MB, used only for
# multi-GPU distributed training) even though we only ever load a pickled
# model and run single-process CPU inference. --no-deps + this explicit
# list is what excludes it; letting pip resolve dependencies normally pulls
# it back in.
#
# Also caught by --no-deps: pyarrow, which nothing in src/ imports directly
# but which pandas needs at runtime for pd.read_parquet — omitting it made
# the container start, then fail on the first parquet read in the lifespan
# handler. A reminder that "grep for imports" undercounts real runtime deps
# whenever a library pulls in an optional backend implicitly.
